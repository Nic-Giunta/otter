# Governance

## Maintainer roles

Maintainers review code, triage issues, steward design decisions, release packages, and protect project quality.

## Contributor expectations

Contributors should write tests, update docs, use English in project-facing text, avoid copying external source code, and discuss major design changes before implementation.

## RFC process

Large changes should be proposed through design issues or RFC pull requests describing motivation, API, compatibility, alternatives, and migration impact.

## Release process

Releases should include changelog entries, CI success, version updates, documentation checks, and package verification.

## Deprecation policy

Breaking changes should provide warnings or migration guidance when practical. Public APIs require explicit deprecation notes.

## Security process

Security reports should follow `SECURITY.md`. Maintainers should acknowledge reports, investigate privately, and publish fixes responsibly.
